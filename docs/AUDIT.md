# Карта аудита

Автоматизируемые пункты ТЗ сопоставлены с проверками ниже. Разговор с автором
и оценка его понимания остаются устной частью аудита; тесты её не заменяют.

## Функциональные требования

| --- | --- |
| Go, стандартная библиотека, структура, 3 бинарника | `go.mod`, `cmd/*`, `make all`, CI |
| 11 команд и корректные пустые стеки | `internal/operations/operations_test.go` |

| `2 1 3 6 5 8` — меньше 9 команд | `TestAuditSixAndIntegerEdges`, 7 команд в сквозном аудите |
| Ошибки чисел и дубликатов в stderr | `TestNumbers`, `TestExactCLIAudit`, сквозной аудит |

## Испытания устойчивости

- Все **5913** перестановок списков длиной 1–7; независимая проверка кратчайших
  расстояний по всем состояниям при n ≤ 5.
- **10 000** списков длиной 100, генератор Go `math/rand`, seed **2008**:
  максимум **594**, среднее **539,54**, ни одного нарушения границы `<700`.
- Дополнительно **100** случайных наборов чисел через собранные бинарники,
  отдельный Python-генератор с seed 2008: максимум **574** операции.
- Возрастание, убывание, циклический сдвиг, чередование крайних значений и случайный
  порядок на размерах 8–10 000, включая границу смены алгоритма 512/513.
- Проверка кольцевого стека против независимого списка: **320 000** случайных
  действий при ёмкостях 1–32.
- Нормализация дубликатов, минимальное/максимальное 64-битное число, переполнение,
  пустые аргументы, NUL, Unicode, огромные строки, оборванные инструкции, ошибки I/O.
- HTTP 429/500/503, запрещённый redirect, потеря соединения, отмена, настоящий
  тайм-аут, не-UTF-8, неверный JSON, пустые choices, неверная роль, пустой/слишком
  большой ответ. Проверяется отсутствие токенов и тела ошибки в диагностике.
- Фаззинг чисел, команд, сортировки и JSON-ответов; проверка гонок и `go vet`.

## Воспроизведение

```sh
make fmt-check vet test race audit stress
GOMAXPROCS=4 make fuzz
```

Локальный контрольный запуск 2026-10-01: macOS arm64, Go 1.27.1; **506** сквозных
проверок прошли. Задержанный HTTP-ответ переключился на mock через **10,01 с**.
Первый 40-секундный цикл фаззинга обработал свыше **6,8 млн** входов без падения
или нарушения проверяемых свойств. Эти числа описывают конкретный запуск, не SLA.

CI повторяет проверки на Go 1.25 и 1.27 в Linux и Go 1.27 в macOS. Конкретный
статус опубликован во вкладке **Actions** и badge README.

## Что именно доказано, а что проверено экспериментально

Кратчайший путь для n ≤ 7 следует из полного BFS. Для больших n используются
эвристики; здесь нет доказательства оптимальности или границы `<700` для всех
100! перестановок. Есть воспроизводимые измерения и независимая проверка результатов.

HTTP-интеграция проверена реальными сетевыми запросами к локальным совместимым
тестовым серверам. На машине сборки Ollama установлен, но сервер на `127.0.0.1:11434`
недоступен и локальные модели не обнаружены в стандартном каталоге. Запуск с живой
генеративной моделью поэтому не заявляется. Пример её подключения приведён в README;
проект по ТЗ полностью работает без неё.

Пределы ресурсов и допустимый дополнительный LF в примерах `echo` явно описаны
в README: скрытых специальных веток под значения аудита нет.
