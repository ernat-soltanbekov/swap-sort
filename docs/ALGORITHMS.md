# От двух стопок к программе сортировки

Представьте две стопки карточек. Взять карточку можно только сверху. Положить её
можно сверху другой стопки; ещё разрешено обменять две верхние карточки или
прокрутить стопку. Задача — получить числа по возрастанию в A и убрать всё из B.

## Язык из 11 действий

| Команда | Действие |
| --- | --- |
| `pa` | Верх B переносится на верх A |
| `pb` | Верх A переносится на верх B |
| `sa` / `sb` | Меняются местами первые два значения соответствующего стека |
| `ss` | Одновременно `sa` и `sb` |
| `ra` / `rb` | Верхнее значение уходит вниз |
| `rr` | Одновременно `ra` и `rb` |
| `rra` / `rrb` | Нижнее значение поднимается наверх |
| `rrr` | Одновременно `rra` и `rrb` |

Если значений недостаточно, действие ничего не меняет. В совместной команде
каждый стек обрабатывается самостоятельно: пустой B не мешает вращению A.

Для `[2 1 3]` достаточно `sa`. Для `[3 1 2]` достаточно `ra`.
Для `[1 2 3]` никаких действий не нужно.

## Почему маленькое решение точно кратчайшее

В `internal/sorter/exact.go` состояние кодируется длиной A и порядком всех значений
A, затем B. Для n чисел существует `(n+1)*n!` состояний: n! порядков и n+1 мест
разделения на два стека. Ранги от 0 до 6 позволяют хранить состояние в короткой строке.

Поиск начинается с `[0 1 ... n-1] / []`. Из него перебираются 11 действий, затем
все ещё не посещённые состояния на расстоянии 2, затем 3 и так далее. Все рёбра
стоят одну команду, поэтому первое посещение имеет минимальную длину.

Для каждого нового состояния сохраняется обратная команда, ведущая к уже
известному соседу. `ra` обращается через `rra`, `pa` через `pb`, swap — через
самого себя. Переход push записывается только если состояние изменилось; это
важно, поскольку push из пустого стека не переносит карточку.

При запросе путь читается из готовой таблицы. `sync.Once` защищает ленивое
построение таблиц при одновременных вызовах.

| n | Число перестановок с пустым B | Самое длинное кратчайшее решение |
| --- | ---: | ---: |
| 1 | 1 | 0 |
| 2 | 2 | 1 |
| 3 | 6 | 2 |
| 4 | 24 | 5 |
| 5 | 120 | 8 |
| 6 | 720 | 10 |
| 7 | 5040 | 13 |

Эти значения получены полным перебором. Независимый тест строит свою таблицу
расстояний для n ≤ 5 и сравнивает длины решений, а не только факт сортировки.

## Ранги без переполнения и сравнительной сортировки

Для `[40 -9 12]` относительные позиции равны `[2 0 1]`. Размер и знак исходных
чисел не влияют на решение после такого преобразования.

Восемь стабильных проходов counting sort обрабатывают байты 64-битных ключей.
Побитовое переключение знакового бита упорядочивает отрицательные и положительные
числа в общей беззнаковой шкале. Вычитание крайних целых не используется, поэтому
`MinInt64` и `MaxInt64` не вызывают переполнения. Память — O(n + 256).

## Бинарный radix

На каждом разряде значения с нулевым битом уходят в B (`pb`), с единичным —
прокручиваются в A (`ra`). После прохода все элементы B возвращаются (`pa`).
Двойной разворот порядка при переносе туда и обратно сохраняет стабильность
группы. Проходы идут от младшего бита к старшему.

Верхняя граница — `2*n*ceil(log2(n))` инструкций. На 100 числах этого недостаточно
для аудита по эффективности, зато это предсказуемый вариант для больших входов.

## Группы по рангу

В `bands` следующий элемент отправляется в B, если его ранг попадает в доступное
окно. Малые ранги дополнительно прокручиваются вниз B. Другие элементы A
прокручиваются до подходящей карточки. После разделения максимальный элемент B
подводится к верху кратчайшим вращением и переносится в A.

В результате большие значения оказываются глубже A, а малые — сверху. Проверяются
четыре ширины окна, зависящие от квадратного корня n. Это компромисс между ценой
разделения и ценой обратного переноса.

## Жадная вставка с общими вращениями

Стек B поддерживается в циклическом убывающем порядке. Для каждого кандидата A
находится место вставки в B. Проверяются четыре сочетания направлений вращения.
Одинаково направленные вращения выполняются через `rr` или `rrr` за одну команду.

Цена одинакового направления — максимум из двух расстояний; противоположного —
сумма. Выбирается самая дешёвая текущая вставка. После сокращения A до трёх
значений они сортируются без обращения к B; затем аналогично собирается
циклически возрастающий A. В конце его минимум поднимается наверх.

Индексы мест вставки строятся одним проходом по плотным рангам. Это убирает
лишний внутренний поиск и удерживает планирование в O(n²).

## Безопасное сокращение команд

`ra rb` превращается в `rr`; `rra rrb` — в `rrr`; `sa sb` — в `ss`.
Две взаимно обратные команды вращения или swap удаляются. `pa pb` автоматически
не сокращается: при пустом источнике первая команда может ничего не сделать,
и тогда такая замена поменяла бы результат.

Свойство сохранения состояния проверяется на случайных произвольных программах,
включая пустые стеки и действия, не встречающиеся в оптимальном решении.

## Как проверять независимо

`checker` разделяет исполнитель со всеми режимами, но не выбирает стратегию и
не доверяет итоговому флагу планировщика. Для защиты от общей ошибки исполнителя
есть ещё две реализации-эталона: срезы в Go-тестах и списки Python в сквозном аудите.
Они сравнивают итог с обычной эталонной сортировкой и требуют пустой B.

Для больших списков тесты подтверждают корректность проверенных входов и
измеренные пределы команд. Глобальная оптимальность больших решений из этих
измерений не следует.
