# swap-sort

[![Audit](https://github.com/ernat-soltanbekov/swap-sort/actions/workflows/ci.yml/badge.svg)](https://github.com/ernat-soltanbekov/swap-sort/actions/workflows/ci.yml)

**Два стека. Одиннадцать команд. Проверяемый результат.**

Проект Tomorrow School на Go: `push-swap` строит программу сортировки,
`checker` независимо от планировщика исполняет команды и проверяет результат,
`ai-coach` объясняет фактически полученное решение. Только стандартная библиотека;
для запуска не нужны аккаунт, API-ключ или установленная языковая модель.

Автор — **Yernat «GhostOfAstana» Soltanbekov**: студент Tomorrow School с техническим
образованием и военным прошлым. Ежеутренняя практика боевых искусств с 2008 года
задаёт подход к проекту: повторяемость, точность и проверка результата под нагрузкой.
Профессиональная цель — работа в команде Astana Hub МИИЦР РК.

## Быстрый старт

Нужен Go **1.25 или новее**. Для `make audit` дополнительно нужны Make и Python 3.9+.
На Linux и macOS всё проверяется в GitHub Actions.

```sh
git clone https://github.com/ernat-soltanbekov/swap-sort.git
cd swap-sort
make

ARG="4 67 3 87 23"
./push-swap "$ARG"
./push-swap "$ARG" | ./checker "$ARG"
# OK

./ai-coach explain "5 4 3 2 1"
./ai-coach debug "5 4 3 2 1"
```

Без Make:

```sh
go build -o push-swap ./cmd/push-swap
go build -o checker ./cmd/checker
go build -o ai-coach ./cmd/ai-coach
go test ./...
```

`go.sum` отсутствует намеренно: внешних Go-модулей нет. Исполняемые файлы собираются
в корень проекта и не хранятся в Git. Исходники, тесты, примеры и CI опубликованы.

## Как пользоваться программами

Первое число — верхушка A. B изначально пуст. Поддерживаются одна строка чисел,
отдельные аргументы и их смесь:

```sh
./push-swap "2 1 3 6 5 8"   # 7 команд
./push-swap 2 1 3 6 5 8
./push-swap "0 1 2 3"       # пустой вывод: уже отсортировано
./push-swap                  # пустой вывод
./checker                   # пустой вывод, stdin не читается
printf 'sa\n' | ./checker "2 1"  # OK
printf 'pb\n' | ./checker "2 1"  # KO: B не пуст
printf 'bad\n' | ./checker "2 1" # Error в stderr, код выхода 1
```

`push-swap` пишет только инструкции с переводом строки. При ошибке чисел обе
программы пишут ровно `Error\n` в **stderr**, оставляя stdout пустым.
`checker` завершает работу с кодом 0 и ответом `OK` или `KO` для корректной программы;
некорректный ввод даёт код 1. Ошибка записи результата также приводит к коду 1.

### Контракт ввода

- Десятичные целые от `-9223372036854775808` до `9223372036854775807`.
- Разрешены знак `+`/`-`, ведущие нули и пробельные разделители между числами.
- Дубликаты сравниваются по значению: `01 +1` и `0 -0` — ошибки.
- Пустой аргумент, дробь, переполнение, шестнадцатеричная запись и посторонние
  символы — ошибки. Отсутствие аргументов отличается от аргумента `""`.
- Максимум 10 000 чисел и 1 MiB суммарного текста аргументов.
- Команды чувствительны к регистру, без пробелов; каждую завершает LF или CRLF.
  Незавершённая последняя команда — ошибка.
- Разрешена **одна дополнительная пустая строка в конце после команд**:
  именно её создаёт `echo -e "...\n"` в примерах аудита. Пустые строки внутри,
  две пустые строки в конце и пустая строка без команд — ошибки.
- `checker` принимает до 2 000 000 инструкций, читает поток постепенно и не хранит
  его целиком. Ограничения защищают от случайного исчерпания ресурсов.

## Алгоритмы

| Случай | Решение |
| --- | --- |
| Уже отсортировано | 0 команд |
| До 7 значений включительно | BFS по состояниям двух стеков: доказуемо кратчайший путь |
| Большой список, достаточно `sa` или циклического сдвига | Прямое решение |
| 8–512 значений | Лучшее из radix, жадной вставки с общими вращениями и четырёх вариантов группировки по рангам |
| Больше 512 значений | Бинарный radix с ограниченной вычислительной стоимостью |

Ранги вычисляются восьмью проходами по байтам 64-битных ключей без сравнительной
сортировки. Все изменения порядка затем происходят через разрешённые стековые
инструкции. `sort.Slice` используется только в тестовом эталоне.

Кольцевые буферы выполняют каждую инструкцию за O(1). BFS посещает `(n+1)*n!`
состояний, поэтому ограничен семью значениями. Планирование остальных кандидатов
ограничено O(n²), radix — O(n log n); сокращение соседних команд сохраняет результат.

**Для n > 7 глобальная минимальность не доказана.** Выбирается лучший измеренный
кандидат; результат стресс-тестов не является доказательством для всех 100!
перестановок. На 10 000 воспроизводимых случайных списков из 100 чисел получено
**не больше 594 команд**, среднее **539,54**, при пороге аудита **меньше 700**.
Для всех 120 перестановок пяти чисел максимум — **8** при пороге меньше 12.

Пошаговое объяснение устройства: [docs/ALGORITHMS.md](docs/ALGORITHMS.md).

## AI Coach: обязательные и бонусные режимы

```sh
./ai-coach explain "5 4 3 2 1"
./ai-coach explain "1 2 3 4 5"
./ai-coach debug   "5 4 3 2 1"
./ai-coach compare "9 0 8 1 7 2 6 3 5 4"
./ai-coach chat    "5 4 3 2 1"
# В чате: What does pb do? → What was my previous question? → exit
```

| Режим | Результат |
| --- | --- |
| `explain` | Реальные команды, стратегия, шаги, число операций и рекомендации по коду |
| `debug` | Полная трасса A/B после каждой команды; проверка порядка и пустоты B; при ошибке — анализ и исправление |
| `compare` | Измеренные числа операций, альтернативы с оценками и рекомендация |
| `chat` | Диалог с сохранением исходного решения, вопросов и ответов; `exit` или EOF завершают сеанс |

Программа принимает ровно два аргумента. При неверном числе аргументов или режиме
выводится двухстрочная подсказка из ТЗ в stderr. В ней сохранены обязательные
`explain, debug`; дополнительные `chat, compare` описаны здесь.

Все режимы используют **ту же функцию сортировки**, что и `push-swap`; subprocess
не нужен. `debug` проверяет состояние обычным исполнителем команд. Если решение
корректно, запрос к модели не требуется. Ветка неисправного решения проверяется
тестами с подставленным ошибочным планировщиком, включая полный trace в HTTP-запросе.

Встроенный mock работает детерминированно, без сети и ключей. Он помечен
`Backend: mock (offline)` и не выдаётся за языковую модель. Для небольшого примера
показывается каждый шаг; длинное объяснение сокращает середину, а `debug` сохраняет
полную трассу. Mock-чат отвечает на вопросы о push, вращениях и тестах, может
вспомнить предыдущий вопрос; свободные вопросы поддерживает подключённая модель.

Для ограниченного размера запросов coach принимает **1–100 чисел**. Чат хранит
все сообщения до **20 вопросов**, затем явно завершает сеанс; один вопрос —
до **8192 байт**. Общие рекомендации охватывают разделение ответственности,
регрессионные тесты, независимый эталон, ошибки вывода и отмену запросов.

### Подключение настоящей модели

Переменные окружения полностью определяют backend:

| Переменная | Значение |
| --- | --- |
| `LLM_BASE_URL` | Базовый HTTP(S)-адрес; пустое значение включает mock |
| `LLM_MODEL` | Имя доступной модели; по умолчанию `local-model` |
| `LLM_API_KEY` | Необязательный bearer-токен |

Программа отправляет JSON `{"model": "...", "messages": [...]}` методом POST
на `<LLM_BASE_URL>/chat/completions` и читает `choices[0].message.content`.
Промпт содержит входные числа и фактические команды; для ошибочной трассы — все
состояния. В коде нет адреса или имени конкретного провайдера.

Например, для уже установленной и запущенной локальной модели в Ollama:

```sh
export LLM_BASE_URL=http://localhost:11434/v1
export LLM_MODEL=имя_вашей_установленной_модели
./ai-coach explain "5 4 3 2 1"
```

Для другого совместимого сервера меняются только эти переменные. Готовый шаблон —
[.env.example](.env.example). Файл `.env` автоматически не загружается; при необходимости:

```sh
cp .env.example .env
# Заполните .env своим адресом и именем модели.
set -a
. ./.env
set +a
```

Тайм-аут запроса — **10 секунд**, предел ответа — **1 MiB**. При недоступности,
ошибке HTTP, некорректном JSON, пустом ответе или превышении лимита выводится
понятная причина и mock-ответ в том же формате. Перенаправления не выполняются;
токены, тела ошибочных ответов и приватные детали соединения не попадают в диагностику.
Ответ модели — пояснение, он не изменяет результат сортировки и не исполняет команды.

## Проверка проекта

```sh
make test         # unit-тесты, все перестановки n <= 7, независимый эталон
make audit        # 506 сквозных проверок трёх собранных программ
make stress       # 10 000 списков по 100 чисел + крайние порядки до 10 000 чисел
make race         # проверка гонок
make vet          # статический анализ
make fmt-check    # форматирование
GOMAXPROCS=4 make fuzz  # по 10 секунд: числа, инструкции, сортировка, JSON модели
```

Тесты не требуют внешнего сервиса: локальные HTTP-серверы проверяют настоящие
запросы, два разных backend-конфига, историю чата и фактический тайм-аут.
Образцы лежат в `testdata/`. В CI запускается та же последовательность на Linux
с Go 1.25/1.27 и macOS с Go 1.27.

Матрица соответствия ТЗ и честные границы проверки: [docs/AUDIT.md](docs/AUDIT.md).
Маршрут самостоятельного разбора проекта: [docs/WALKTHROUGH.md](docs/WALKTHROUGH.md).
